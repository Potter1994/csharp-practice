### Day 1:C# 基本語法、型別系統

**驗收標準:能解釋 `var` / `const` / `out` 的差異與用途**
(以下三段原本寫在 Program.cs 底部,搬過來)

- `var`
    編譯時期的型別推斷。編譯器從初始值推出型別後就固定住, 之後不能變

- `const`
    編譯時期常數: 值在編譯時就被直接嵌入到每個使用他的方法, 執行期根本不存在這個變數。
    這帶出一個實務上的坑: 如果你把 const 放在類別庫裡, 改了值之後只重編譯那個類別庫、
    沒重編譯用它的專案, 那些專案會繼續用舊的值, 因為舊值早就被烤進它們的組件裡了。
    所以會對外發布的常數通常用 static readonly 而不是 const。

- `out`
    不用返回複雜結構就能傳出多個值, 編譯器強制方法在返回前賦值給每個 out 參數,
    所以呼叫端保證拿得到值

**程式碼裡用到、但還沒整理的語法**

- `input[^1]` 的 `^` 和 `input[0..^1]` 的 `..` 分別是什麼?為什麼 `[0..^1]` 是「去掉最後一個字元」?
    `input[^1]` 代表的是取得這個 input 最後一位
    `input[0..^1]` 代表的是取 index 0 到最後一位(相當於去掉最後一個字元)


- `{result:F2}` 這種格式字串怎麼運作?還有哪些常用的格式?(提示:`C` 貨幣、`P` 百分比、`N` 千分位)
    這是格式字串, 真的要用到再去查詢就好, 記住這個比較沒有什麼意義


- `double CelsiusToFahrenheit(double c) => c * 1.8 + 32;` 的 `=>` 叫什麼?跟 `{ return ...; }` 寫法有什麼差別、什麼時候不能用?
    1. 叫什麼:
    Expression-bodied member(運算式主體成員)。C# 6 引入(方法、唯讀 property),C# 7 擴充到建構函式、finalizer、property 的 get/set 存取子、indexer。
    不是 lambda —— 它是具名成員的簡寫語法,不是可以賦值給變數的匿名函式。

    2. 跟 { return ...; } 的差別:
    Release 編譯後 IL 完全相同,純語法糖,零效能差異。 差別只在可讀性和語法限制。
    (Debug 模式下 block 版會多出 nop 和一個暫存變數,那是為了讓除錯器能在 return 那行下中斷點,跟寫法好壞無關。)

    3. 什麼時候不能用:
    只能放「單一運算式」—— 所有陳述式都不行


- `TryParseTemperature` 直接寫在 top-level statement 裡,這種函式叫什麼?跟寫在 class 裡的 static 方法差在哪?
    <!-- 這種函式一樣是跟寫在 class 裡面的 method 一樣, static 則是類別的方法(不會被建立在實例上, 僅供類別使用) -->
    這種叫 local function(區域函式),C# 7.0 加的。你答「跟 class 裡的 method 一樣」—— 但它有兩個 class 方法沒有的特性,而且剛好是你 Day 1 程式碼裡用得到的:

    只在宣告它的範圍內可見 —— 外面完全看不到,連同一個檔案的其他地方都不行
    可以捕捉外部的區域變數(閉包)—— static 方法完全做不到

    另外兩個實用差異:

    可以在宣告之前呼叫(編譯器會先掃過)
    可以標 static 禁止捕捉:static bool TryParse(...),避免意外的閉包配置

    跟 lambda 的差異也值得一起記:local function 有名字、可以遞迴、不配置委派物件,效能比 lambda 好。所以能用 local function 就不要用賦值給變數的 lambda。


- 練習 1 要求的 `??`,跟 `?.`、`??=` 分別在做什麼?為什麼 C# 需要這些而 JS 的 `??` 是後來才加的?
    `??`: 當前一個為 null 實為後面那個
    `?.`: 當前一個為 null 就返回 null
    `??=`: 當前一個為 null 就等於後面那個
